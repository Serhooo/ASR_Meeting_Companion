# 🎙 Meeting Companion — локальный ИИ-секретарь встреч (Windows)

Записывает встречу (микрофон + системный звук), распознаёт речь локально
(GigaAM, русский) и строит протокол: **Решения · Договорённости · Следующие шаги**
через локальную LLM (Ollama). Всё выполняется на вашем компьютере —
данные не покидают машину (кроме однократной загрузки весов моделей).

![Python 3.10+](https://img.shields.io/badge/python-3.10+-blue) ![Windows](https://img.shields.io/badge/Windows-10%2F11-lightgrey)

## Зависимости

| Компонент | Назначение | Как ставится |
|---|---|---|
| Python 3.10+ | интерпретатор | уже в проекте: `python-portable/` (портативный, без установки) либо системный |
| sounddevice, numpy, scipy | захват и обработка аудио | `pip install -r requirements.txt` |
| customtkinter | GUI (тёмная тема) | там же |
| PyTorch (CPU по умолчанию) | инференс GigaAM | там же; для GPU — CUDA-сборка (см. ниже) |
| GigaAM-v3 | распознавание речи (русский) | pip-пакет + веса в `models_gigaam/` |
| Ollama | локальная LLM для протокола | портативная: бандл в `tools/` → распаковывается в `ollama/`, модели в `ollama_models/` |

> **Про FFmpeg:** приложение записывает и распознаёт аудио **без ffmpeg**
> (собственный тензорный путь в GigaAM). FFmpeg нужен только при запуске
> gigaam напрямую.

## Установка с нуля (для другой машины)

```powershell
cd ASR_Meeting_Companion
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
```

### GPU NVIDIA (опционально, на машине с видеокартой)

Установите CUDA-сборку PyTorch **вместо** CPU-сборки:

```powershell
pip uninstall torch torchaudio
pip install torch torchaudio --index-url https://download.pytorch.org/whl/cu126
```

В приложении: Настройки → Устройство ASR → «Авто» (или «CUDA»).
При отсутствии GPU режим «CUDA» покажет понятную ошибку, «Авто» сам
упадёт на CPU (PRD п. 2.1).

### Ollama — портативная, внутри проекта (по умолчанию)

Никакой системной установки: официальный бандл лежит в `tools/ollama-windows-amd64.zip`,
приложение распаковывает его в `ollama/`, держит модели в `ollama_models/`
(переменная `OLLAMA_MODELS` указывает внутрь проекта) и запускает
`ollama serve` как собственный дочерний процесс на `127.0.0.1:11434`.

* Всё уже сделано: бандл распакован, сервер проверен.
* Скачивание модели: **Настройки → Портативная Ollama → «Скачать модель»**
  (офлайн-повторно не требуется — файлы останутся в папке проекта).
* Папку проекта можно перенести на другой компьютер вместе с `ollama/` и
  `ollama_models/` — Ollama поедет с ней (портативность).
* Опционально, если хотите системную Ollama вместо портативной:
  `winget install Ollama.Ollama` + `ollama pull llama3.2:3b` — приложение
  сначала проверяет `localhost:11434` и подхватит любой работающий сервер.

## Запуск

**Способ А (простой):** двойной клик по **`run.bat`** — скрипт сам подбирает
Python в порядке: портативный (`python-portable\`) → системный → тихая
установка из бандла `tools\python-3.13.15-amd64.exe` (если нет совсем).

**Способ Б (ручной):**
```powershell
python-portable\python.exe main.py
```

> Портативный Python со всеми зависимостями (torch, gigaam, customtkinter…)
> лежит внутри проекта — **на чистом компьютере ничего скачивать не нужно**.

> Подробная пользовательская инструкция — **`HELP.md`** (кнопка «? Справка»
> в шапке приложения открывает её).

1. (Опционально) Заполните вкладку **«Тема»** — повестку и участников совещания;
   LLM использует её как контекст при составлении протокола (тема сохраняется
   между запусками и попадает в шапку экспорта .md).
2. Выберите режим: **«Встреча»** (по умолчанию — запись → протокол) или
   **«Реалтайм»** (текст транскрипта появляется по мере речи, задержка ~1–2 с
   после конца фразы; после остановки всё равно строится точный протокол).
3. Нажмите **«Записать встречу»** — пишутся микрофон и системный звук
   (Стерео микшер Realtek на этой машине). В режиме «Встреча» доступна
   кнопка **«⏸ Пауза»** — при снятии с паузы в будущий транскрипт встаёт
   тайм-код перерыва `[MM:SS] ⏸ Перерыв (пауза N с)`; таймер показывает
   только записанное время.
4. Говорите; остановите кнопкой **«⏹ Остановить запись»**.
5. Запись сохраняется в `cache/meeting_cache.wav`. Обработка запускается
   **отдельной кнопкой «Обработать запись»** — вы сами выбираете момент
   (можно переобработать ту же запись после смены настроек).
6. Идёт распознавание (прогресс-бар, % и номер сегмента) — на CPU час
   встречи ≈ 15–40 минут в зависимости от процессора.
7. Транскрипт с таймкодами `[MM:SS]` появится справа; затем локальная Ollama
   соберёт протокол на вкладках слева (сервер поднимается автоматически).
8. **«Экспорт протокола в MD»** или **«Экспорт в Word (.doc)»** — файл
   в папке `exports/` (.doc открывается Word/LibreOffice/WPS без доп. библиотек).

## Настройки (кнопка ⚙)

| Параметр | По умолчанию | Описание |
|---|---|---|
| Устройство ASR | Авто | **Авто / CPU / CUDA** — выбор устройства инференса (PRD 2.1) |
| Версия GigaAM | v3_e2e_ctc | v3_e2e_ctc (пунктуация, быстрее) / v3_e2e_rnnt / v3_ctc / v3_rnnt |
| Адрес Ollama | http://localhost:11434 | локальный сервер |
| Модель Ollama | llama3.2:3b | любая загруженная (`ollama list`) |

Настройки сохраняются в `config.json` рядом с `main.py`.

```
app/gui/                 # Модуль 4: CustomTkinter (тёмная тема, неон-зелёный)

```

## Как это работает (соответствие PRD)

* **Захват** — два потока sounddevice (микрофон + loopback) пишутся в
  временные WAV (потокобезопасно, RAM не растёт), микшируются в 16 kHz моно
  и сохраняются как `cache/meeting_cache.wav`.
* **Распознавание** — GigaAM-v3 на torch: `resolve_device()` реализует
  Авто/CPU/CUDA; аудио режется на чанки (60 с по умолчанию) — защита
  VRAM/RAM + точный прогресс; таймкоды = позиция чанка.
* **Суммаризация** — REST в локальный Ollama (`/api/chat`), системный промпт
  из PRD, разбор ответа на три блока по вкладкам.
* **Приватность** — в рантайме нет ни одного внешнего запроса; первый запуск
  скачивает веса один раз (GigaAM CDN + `ollama pull`).

## Проверка автономности (PRD, п. 4.1)

Приложение спроектировано так, что **после первичной настройки внешняя сеть
не нужна вовсе**. Как гарантировано:

1. **Единственный сетевой клиент в коде** — `urllib` к адресу Ollama
   (по умолчанию `http://localhost:11434` — это loopback, трафик не покидает
   машину даже теоретически).
2. **Веса GigaAM** скачиваются CDN один раз в `models_gigaam/` (внутри
   проекта — едут вместе с ним на другой ПК); при наличии
   кэша загрузчик возвращает файл локально, не трогая сеть (проверено
   исходниками `_download_file`).
3. **`main.py` выставляет `HF_HUB_OFFLINE=1`, `TRANSFORMERS_OFFLINE=1`** —
   даже ленивые импорты HuggingFace/pyannote физически не смогут выполнить
   сетевой запрос из рантайма.
4. **Диагностика при старте**: статусная строка показывает «🔒 Автономный
   режим» и локальный стек (веса ✓/скачаются, Ollama запущена/нет).

**Простой тест:** отключите Wi-Fi/кабель после установки — запись,
распознавание и экспорт .md продолжат работать; Ollama отвечает только
протоколом (она локальная). Единственная «сеть», которую вы увидите, —
pip при обновлении зависимостей (это уже не приложение).

Опционально — жёсткое правило файрвола (PowerShell от администратора):

```powershell
# Запретить python.exe доступ в интернет, разрешить только loopback
New-NetFirewallRule -DisplayName "Meeting Companion offline" `
  -Direction Outbound -Program "C:\Path\To\python.exe" `
  -Action Block -RemoteAddress Internet
```

> Примечание: если вы в настройках смените адрес Ollama на внешний — данные
  транскрипта уйдут по сети **по вашему решению**; по умолчанию только localhost.


## Устранение проблем

* **«Устройство loopback не найдено»** — включите «Стерео микшер» в записывающих
  устройствах Windows (Панель управления → Звук → Запись → ПКМ → Показать
  отключённые устройства → включить «Стерео микшер»).
* **«Ollama недоступна»** — запустите Ollama (иконка в трее) или `ollama serve`.
* **Медленно на CPU** — нормально: берите компактную модель LLM (3B) и
  `v3_ctc` вместо rnnt; прогресс виден в реальном времени.
* **Смена устройства/модели** — Настройки → Сохранить (модель выгружается
  из памяти автоматически).
